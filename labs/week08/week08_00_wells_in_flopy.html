Week 8, notebook 0: Wells in FloPy

HWRS 564a · Fall 2026

In Week 7 you developed steady state models. This notebook looks at wells more closely, on a model simple enough that we can check MODFLOW against formulas you can work out by hand.

There are three parts:

  1. How to describe wells to FloPy with the WEL package
  2. One well in an aquifer with no other flow, compared with the Thiem equation
  3. One well in an aquifer with regional flow, and how its capture zone grows with the pumping rate

How to use this notebook

Run each cell with Shift+Enter. Cells marked # YOUR TURN have something for you to write. Cells marked # CHECK test your answer and raise an error if it is wrong.

Learning objectives

By the end of this notebook you can:

  1. Write the stress_period_data for one or more wells and confirm the pumping in the water budget
  2. Compare model heads near a well with the Thiem equation
  3. Trace the capture zone of a well in regional flow
  4. Estimate the width of a capture zone from the pumping rate, the transmissivity, and the regional gradient

Part 2: The model

One confined layer, 2 km by 2 km, with 20 m cells.

Grid 101 rows, 101 columns, 20 m cells
Layer top at 0 m, bottom at −20 m, so 20 m thick
Hydraulic conductivity 10 m/d
Transmissivity \(T = Kb\) = 10 × 20 = 200 m²/d

The grid has an odd number of rows and columns so that one cell sits exactly in the middle: row 50, column 50.

The function below builds and runs the model. It takes:

  • wells: a list of wells, in the format described in Part 3. Use an empty list for no wells.
  • west_head and east_head: the constant heads on the west and east edges
  • constant_head_all_sides: if True, the north and south edges are constant head too. If False, they are no-flow boundaries.
N = 101                  # rows and columns
DELR = 20.0              # cell size, m
HK = 10.0                # hydraulic conductivity, m/d
TOP, BOTM = 0.0, -20.0   # layer top and bottom, m
T = HK * (TOP - BOTM)    # transmissivity, m2/d
MID = N // 2             # row and column of the middle cell


def run_model(name, wells, west_head=10.0, east_head=10.0,
              constant_head_all_sides=False):
    """Build and run the model. Returns (model, head, workspace)."""
    ws = RUN / f"week08_wells_{name}"
    ws.mkdir(parents=True, exist_ok=True)

    m = flopy.modflow.Modflow(name, model_ws=str(ws), exe_name=str(MF_EXE))
    flopy.modflow.ModflowDis(m, nlay=1, nrow=N, ncol=N, delr=DELR, delc=DELR,
                             top=TOP, botm=BOTM, nper=1, steady=True)

    ibound = np.ones((1, N, N), dtype=int)
    ibound[:, :, 0] = -1           # west edge
    ibound[:, :, -1] = -1          # east edge
    if constant_head_all_sides:
        ibound[:, 0, :] = -1       # north edge
        ibound[:, -1, :] = -1      # south edge

    # starting head: a straight line from the west head to the east head
    strt = np.ones((1, N, N)) * np.linspace(west_head, east_head, N)
    flopy.modflow.ModflowBas(m, ibound=ibound, strt=strt)

    flopy.modflow.ModflowLpf(m, hk=HK, laytyp=0, ipakcb=53)
    if wells:
        flopy.modflow.ModflowWel(m, stress_period_data={0: wells}, ipakcb=53)
    flopy.modflow.ModflowPcg(m, rclose=1e-3)
    flopy.modflow.ModflowOc(m, stress_period_data={(0, 0): ["save head", "save budget"]})

    m.write_input()
    success, buff = m.run_model(silent=True, report=True)
    assert success, "MODFLOW did not finish:\n" + "\n".join(buff[-10:])
    head = flopy.utils.HeadFile(str(ws / f"{name}.hds")).get_data()
    return m, head, ws


print(f"transmissivity T = {T:.0f} m2/d")

Part 3: The WEL package

FloPy takes wells as a dictionary called stress_period_data. The key is the stress period number, and the value is a list with one entry per well:

{0: [[layer, row, column, rate],
     [layer, row, column, rate]]}
  • Layer, row, and column count from zero.
  • A negative rate takes water out of the cell. A positive rate injects water.
  • The rate is in the model’s units. Here that is m³/d.

Our run_model function builds the dictionary for stress period 0, so you only pass it the list. Here is one well in the middle cell, pumping 400 m³/d. All four edges are held at 10 m.

one_well = [[0, MID, MID, -900.0]]

m_one, head_one, ws_one = run_model(
    "one_well", one_well, constant_head_all_sides=False #True
)

print("what FloPy stored for stress period 0:")
print(m_one.wel.stress_period_data[0])
what FloPy stored for stress period 0:
[(0, 50, 50, -900.)]

FloPy stores the wells as a table with columns k, i, j, and flux. Those are MODFLOW’s names for layer, row, column, and rate.

Always confirm the pumping in the water budget. A well in the wrong cell, or with the wrong sign, still runs.

def print_budget(ws, name):
    """Print the budget terms that are not zero."""
    budget = flopy.utils.MfListBudget(str(ws / f"{name}.list")).get_data()
    for row in budget:
        term = row["name"].decode()
        if term != "tslen" and abs(row["value"]) > 1e-6:
            print(f"  {term:20s} {row['value']:10.2f}")

Part 4: Checking against the Thiem equation

For steady flow to a well in a confined aquifer, the Thiem equation gives the difference in head between two distances from the well, \(r_1\) and \(r_2\):

\[h(r_2) - h(r_1) = \frac{Q}{2\pi T}\ln\frac{r_2}{r_1}\]

\(Q\) is the pumping rate as a positive number. Head rises as you move away from the well, quickly at first and then more slowly.

To compare with the model, take the heads along row 50 from the well cell eastward. Cell centres are 20 m apart, so those cells are at 0, 20, 40, … m from the well.

Part 5: A well in regional flow

Now let the groundwater flow from west to east. Set the west edge to 10 m and the east edge to 0 m, with no-flow boundaries on the north and south. The edges are 2,000 m apart, so the regional gradient is

\[i = \frac{10 - 0}{2000} = 0.005\]

Without a well, head falls in a straight line and every metre of aquifer width carries the same flow:

\[T\,i = 200 \times 0.005 = 1 \text{ m}^3\text{/d per metre of width}\]

GRADIENT = 10.0 / 2000.0

m_none, head_none, ws_none = run_model("no_well", [], west_head=10.0, east_head=0.0)
print_budget(ws_none, "no_well")
print(f"\nT x i x width = {T * GRADIENT * N * DELR:.0f} m3/d")

The flow through the model matches \(T\,i\) times the width of the model.

Now add the well. Water that enters from the west either reaches the well or passes by to the east edge. The capture zone is the part of the aquifer whose water ends up in the well.

To find it, we start particles in a ring around the well and follow the flow backwards. Every path found that way is a path that leads to the well. The function below does that. It needs the flow between cells, which MODFLOW saves in the .cbc file, and FloPy turns into a flow direction at each cell centre.

def trace_to_well(m, ws, name, n_particles=120, step=5.0, n_steps=500):
    """Follow the flow backwards from a ring around the middle cell.

    Returns an array of shape (n_steps, n_particles, 2) holding the x and y of
    each particle at each step. Positions are NaN after a particle leaves the
    model.
    """
    cbc = flopy.utils.CellBudgetFile(str(ws / f"{name}.cbc"))
    frf = cbc.get_data(text="FLOW RIGHT FACE")[0]
    fff = cbc.get_data(text="FLOW FRONT FACE")[0]
    qx, qy, _ = flopy.utils.postprocessing.get_specific_discharge((frf, fff, None), m)

    # cell centres, with y increasing to the north (row 0 is the north edge)
    x = (np.arange(N) + 0.5) * DELR
    y = (np.arange(N) + 0.5) * DELR
    fx = RegularGridInterpolator((y, x), qx[0][::-1], bounds_error=False)
    fy = RegularGridInterpolator((y, x), qy[0][::-1], bounds_error=False)

    angle = np.linspace(0, 2 * np.pi, n_particles, endpoint=False)
    pos = np.column_stack([x[MID] + 1.5 * DELR * np.cos(angle),
                           y[MID] + 1.5 * DELR * np.sin(angle)])
    paths = np.full((n_steps, n_particles, 2), np.nan)
    for k in range(n_steps):
        paths[k] = pos
        q = np.column_stack([fx(pos[:, ::-1]), fy(pos[:, ::-1])])
        speed = np.hypot(q[:, 0], q[:, 1])
        pos = pos - step * q / speed[:, None]        # minus: against the flow
    return paths

The grey lines are head contours and the blue lines are flow paths that end at the well. Flow is from left to right. The blue region is the capture zone.

Two things to notice:

  • The capture zone extends upstream to the west edge, and gets wider going upstream.
  • It extends only a short way downstream of the well. The point where it ends is called the stagnation point. Water east of it flows away from the well.

Both can be estimated by hand.

Width. The well takes \(Q\). Each metre of aquifer width carries \(T\,i\). So far upstream, the well needs a strip of aquifer this wide:

\[w = \frac{Q}{T\,i}\]

Stagnation point. The well pulls water toward it at a rate that falls off with distance. At the stagnation point that pull exactly balances the regional flow. The distance downstream from the well is

\[x_s = \frac{Q}{2\pi T\,i}\]

Three pumping rates

Now run the model at 200, 400, and 800 m³/d and measure both quantities from the model:

  • the width of the capture zone where it meets the west edge
  • the stagnation point, which lies between the last cell face east of the well with flow toward the well and the first one with flow toward the east
def measure(m, ws, name, paths):
    """Capture-zone width at the west edge, and the two cell faces that
    bracket the stagnation point (distances east of the well)."""
    last = np.array([p[~np.isnan(p[:, 0])][-1] for p in paths.transpose(1, 0, 2)])
    reached_west = last[last[:, 0] < 2 * DELR]
    width = float(np.ptp(reached_west[:, 1]))

    cbc = flopy.utils.CellBudgetFile(str(ws / f"{name}.cbc"))
    frf = cbc.get_data(text="FLOW RIGHT FACE")[0]
    east_of_well = frf[0, MID, MID:]              # flow through each cell's east face
    k = int(np.argmax(east_of_well > 0))          # first face with flow to the east
    return width, ((k - 0.5) * DELR, (k + 0.5) * DELR)

Doubling the pumping rate doubles the width of the capture zone and doubles the distance to the stagnation point. Both estimates are proportional to \(Q\).

The stagnation distances from the model bracket the estimates.

The widths from the model are smaller than \(Q/(T\,i)\), and the gap grows with the pumping rate. That is expected. \(Q/(T\,i)\) is the width far upstream, and the capture zone is still widening where it meets the west edge of our model, 1 km from the well. At the well itself the capture zone is half as wide, \(Q/(2T\,i)\).

These estimates assume a uniform aquifer, a uniform regional gradient, no recharge, and a boundary far away. Real sites break all of those, which is why capture zones are usually worked out with a model. The formulas are still worth knowing: they tell you roughly what the model should give, and what happens to the answer if \(Q\), \(T\), or \(i\) changes.
