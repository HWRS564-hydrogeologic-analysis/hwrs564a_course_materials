Booleans

Comparison produces a value

> isn’t a question you ask. It is an operator that returns a bool.

That distinction matters because you can store the result, pass it to a function, or put it in a list. It is a value like any other.

The operators

== != equal, not equal
< > <= >= ordering
and or not combining
in membership

= assigns. == compares. Writing if x = 5: is a SyntaxError, which is the good outcome — in C it silently assigns and the bug lives for years.

And from Week 2: never == on floats. 0.1 + 0.2 == 0.3 is False.

Combining them

Python reads left to right and stops as soon as the answer is settled. In a and b, if a is false, b never runs. That is how you write if n > 0 and total / n > 5 without dividing by zero.

Branching

if and else

if water_level > screen_bottom:
    print("Dry — the water table is below the screen.")
else:
    print("Wet.")
  • The : is required
  • The indented block is the body — four spaces
  • Python uses indentation where other languages use braces

IndentationError is not Python being fussy. Indentation is the syntax.

More than two outcomes

if decline_m > 30:
    status = "severe"
elif decline_m > 10:
    status = "moderate"
elif decline_m > 0:
    status = "mild"
else:
    status = "stable or recovering"

Python takes the first true branch and skips the rest.

Put > 0 first and every declining well is “mild” — the other branches become unreachable. Order your conditions from most specific to least.

Your turn: classify a well

Set category to "deep" if the well is deeper than 500 ft, "moderate" if deeper than 150 ft, and "shallow" otherwise.

Hint

Test the most restrictive condition first, or the deep wells get caught by the moderate branch.

Solution

if well_depth_ft > 500:
    category = "deep"
elif well_depth_ft > 150:
    category = "moderate"
else:
    category = "shallow"

"moderate". Note there is no and well_depth_ft <= 500 on the second branch — you only reach it when the first one was false, so it is already implied.

Repeating

for walks a sequence

depth is a name that takes each value in turn. It is not special, and it still exists after the loop finishes — holding the last value.

The point of a loop is to accumulate

total = 0.0                  # start empty
for depth in depths:
    total = total + depth    # add to it
print(total / len(depths))   # use it

Same shape for building a list:

depths_ft = []
for depth in depths:
    depths_ft.append(depth * 3.28084)

Initialize before the loop, not inside it. Putting total = 0.0 inside the body resets it every pass and you get the last value back.

enumerate and zip

Reach for these before range(len(...)). zip stops at the shortest sequence — silently — so two lists of different lengths lose data without complaint.

Your turn: count the dry wells

A well is dry when its water level is below its screen bottom — that is, when the depth number is larger.

Hint 1

Depth counts downward from the land surface. Deeper means a bigger number.

Hint 2

n_dry = n_dry + 1, or the shorthand n_dry += 1.

Solution

if depth > bottom:
    n_dry = n_dry + 1

1 — only C-22, at 88.4 m against an 80.0 m screen bottom.

Half the sign errors in groundwater work come from mixing depth below surface with elevation above datum. They run in opposite directions.

while

Loop until something is true

Use while when you don’t know how many steps it takes.

The one rule: something in the body must eventually make the condition false. If not, the cell runs forever and you interrupt the kernel (■).

Always carry a guard

day = 0
MAX_DAYS = 1000

while storage > 50.0 and day < MAX_DAYS:
    storage = storage * (1 - k)
    day += 1

if day == MAX_DAYS:
    print("gave up — did not converge")

You will write this exact pattern twice more: in Week 4 when your bisection solver needs a stopping rule, and in Week 12 when MODFLOW hits its iteration limit and tells you so.

A solver without a maximum iteration count isn’t a solver. It’s a hang.

Your turn: how many years?

A well’s water level is 62 m down and falling 0.8 m per year. The pump intake is at 95 m. How many whole years until the pump is above the water?

Hint

Keep going while the water is still above the intake — that is, while depth is still less than intake.

Solution

while depth < intake:
    depth = depth + rate
    years += 1

42 years. Worth sanity-checking by hand: 33 m to fall at 0.8 m/yr is 41.25, which rounds up to 42 whole years. Always do that check — a loop that is off by one looks exactly like a loop that is right.
