What a model needs

Six questions, six packages

MODFLOW does not have a “model file.” It has a package per question.

Question Package
What shape is the domain, and in what units? DIS
Which cells are active, and where do we start? BAS
How permeable is it? LPF
Who is pumping? WEL
What comes in from above? RCH
How do we solve, and what do we save? PCG, OC

That table is the mental model. Every model you build for the rest of the semester is these six answers, occasionally plus a seventh.

Your turn: size the grid

Our basin is discretized at 250 m cells, 40 rows by 60 columns, one layer. Work out how big the domain actually is, in kilometres.

Hint

delr is the width of a column, so the east-west extent is set by ncol. Metres to kilometres is a factor of 1000.

Solution

width_km = ncol * delr / 1000
height_km = nrow * delc / 1000

15 km by 10 km, in 2400 cells. Worth doing this arithmetic before you run anything — a grid that turns out to be 15 m across is a mistake you want to catch now, not after a twenty-minute solve.

Writing it down

Discretization

mf = flopy.modflow.Modflow("scbasin", model_ws=ws, exe_name=mf2005)

flopy.modflow.ModflowDis(
    mf, nlay=1, nrow=40, ncol=60,
    delr=250.0, delc=250.0,      # cell size
    top=420.0, botm=340.0,       # elevations, not thicknesses
    nper=1, steady=True,         # one steady-state stress period
)

top and botm are elevations, not thicknesses. Getting this backwards produces a model with negative thickness that fails in a way the error message does not explain.

Boundaries and starting heads

ibound = np.ones((1, 40, 60), dtype=int)
ibound[:, :, 0] = -1        # constant head upgradient
ibound[:, :, -1] = -1       # constant head downgradient

strt = np.full((1, 40, 60), 412.0)
strt[:, :, -1] = 402.0

flopy.modflow.ModflowBas(mf, ibound=ibound, strt=strt)

ibound: 1 active, 0 inactive, -1 constant head. In a steady-state run strt is only a starting guess except in the -1 cells, where it is the boundary condition itself.

Stresses

flopy.modflow.ModflowLpf(mf, hk=12.0, laytyp=1, ipakcb=53)
flopy.modflow.ModflowWel(
    mf, stress_period_data={0: [[0, 20, 30, -4000.0]]}, ipakcb=53
)
flopy.modflow.ModflowRch(mf, rech=1.4e-4, ipakcb=53)

The well entry is [layer, row, column, rate], zero-indexed, and negative is extraction. A sign error here is the single most common way to end up presenting a mound where you meant a cone.

Your turn: the pumping rate

A water provider reports the well pumps 730 acre-feet per year. MODFLOW wants m³/day, negative for extraction.

Hint 1

Convert the volume first, then divide by the number of days.

Hint 2

Don’t forget the sign. MODFLOW reads a positive WEL rate as injection.

Solution

rate_m3_per_day = -acre_feet_per_year * M3_PER_ACRE_FOOT / DAYS_PER_YEAR

About -2466.9 m³/d. Roughly 60% of the 4000 m³/d we are about to simulate — so expect a correspondingly shallower cone.

Hitting go

Run it, then check that it ran

mf.write_input()
success, buff = mf.run_model(silent=True, report=True)

assert success, "MODFLOW did not converge:\n" + "\n".join(buff[-20:])

FloPy does not raise when a model fails to converge. It returns (success, buff) and carries on. If you ignore success, you will happily plot the last thing that landed in the .hds file and present it as a result.

Every model you run in this course, from here to Week 15, gets that assert.

report=True is not optional. With silent=True alone FloPy hands back an empty buff, so the assertion fires with no diagnostic in it — the one moment you needed one.

Your turn: is that drawdown a lot?

The aquifer is 80 m thick and the well cell sits at the head printed above. Express the drawdown as a percentage of saturated thickness.

Hint

Saturated thickness is the undisturbed head minus the aquifer bottom, not the 80 m you were told — that is the geologic thickness.

Solution

drawdown = head_undisturbed - head_at_well
percent_of_thickness = 100 * drawdown / (head_undisturbed - aquifer_bottom)

3.17 m, about 4.5% — small enough that the confined approximation holds. Above roughly 25% you should be asking whether laytyp=1 is doing real work.
