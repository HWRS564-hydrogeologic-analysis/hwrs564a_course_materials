Confined or not

The difference is one argument

laytyp=0 — confined

\[T = Kb\]

\(b\) is fixed. The equations are linear. One pass of the solver.

laytyp=1 — convertible

\[T = K(h - z_{bot})\]

\(T\) depends on the head you are solving for. Nonlinear. Iterate.

This is a statement about the aquifer, not a numerical convenience. Convertible is right when the water table is the top of the saturated zone.

Which is why pumping is worse unconfined

  • Pumping lowers head
  • Lower head means less saturated thickness
  • Less thickness means lower transmissivity
  • Lower transmissivity means more drawdown for the same rate

A feedback loop, and the reason unconfined cones are deeper and narrower than confined ones for the same well.

Your turn: transmissivity as head falls

Hint

Transmissivity is conductivity times saturated thickness, and the saturated thickness is head minus the layer bottom.

Solution

T = hk * (h - z_bot)

3,120 down to 2,400 m²/d — a 23% loss of transmissivity for 60 m of decline.

And that is the whole difficulty. MODFLOW cannot compute \(T\) until it knows \(h\), and it cannot compute \(h\) without \(T\). So it guesses, solves, recomputes, and solves again — which is Week 4’s iteration material, on 2,400 coupled equations.

When it won’t converge

Same basin, one argument different

flopy.modflow.ModflowLpf(mf, hk=12.0, laytyp=1, ipakcb=53)
FAILED TO MEET SOLVER CONVERGENCE CRITERIA            1  TIME(S)

Exactly the model that converged last week, now failing. This is the normal condition of groundwater modelling, not a sign you did something wrong.

The two causes

A bad starting guess

strt was a flat 660 m against boundaries of 620 and 680.

So the first transmissivity estimate is wrong everywhere.

A solver that gives up

mxiter=20 by default — twenty chances to settle a transmissivity that keeps moving.

In the lab you try the first on its own. It is not enough. Debugging a solver is a search over several settings, not a sequence of fixes that each help.

The four arguments worth adjusting

Argument Default What it does
mxiter 20 outer iterations — recomputes transmissivity
iter1 30 inner iterations per outer one
hclose 1e-3 head-change tolerance for “converged”
relax 1.0 damps oscillation between iterations

For a nonlinear problem, mxiter is usually the one.

flopy.modflow.ModflowPcg(mf, mxiter=200, iter1=50,
                         hclose=1e-3, rclose=1e2, relax=0.98)

Your turn: which knob?

A convertible-layer model fails with the message above. You have one change to try first.

Hint

The problem is that transmissivity keeps changing between outer iterations. Which setting controls how many outer iterations it gets?

Solution

first_try = "a"

mxiter controls the outer loop, which is exactly what a nonlinear problem needs more of.

b makes it worse — a tighter tolerance is harder to reach, not easier. c changes the question you were asked, which is sometimes necessary but is not a fix. d changes the physics to something you have reason to believe is wrong.

Only a leaves the problem alone and gives the solver a fair chance at it.

Converged is not correct

All you have established is that the solver found a self-consistent answer.

Whether it is the right answer depends on the boundary conditions, the conductivity field, and the recharge — none of which the solver knows anything about.

Check the budget discrepancy too. And then check whether the answer is physically sensible, which no number can do for you.

Dry cells

What happens when a cell empties

If head in a convertible cell falls below the layer bottom, there is no saturated thickness left. MODFLOW marks the cell dry, sets its head to -1e30, and removes it from the solution.

The sentinel value problem, again

One -1e30 destroys the entire colour scale.

Exactly what -999 did to the water-level series in Week 6. Same lesson, different decade of software.

dry_mask = head[0] < -1e29
head_masked = np.where(dry_mask, np.nan, head[0])

And note: 1e30 positive means inactive (ibound = 0). -1e30 means dry. Different problems, similar-looking numbers.

Your turn: mask them

Hint

Compare against a threshold near the sentinel rather than to -1e30 exactly — never test a float with ==. Then np.where to substitute np.nan.

Solution

dry = head < -1e29
masked = np.where(dry, np.nan, head)

Three dry cells; the wet ones run 659.9 to 665.2 m.

Note < -1e29 rather than == -1e30. Same rule as Week 2: never test a float for equality. MODFLOW’s sentinel is configurable via hnoflo, so the exact value is not something to rely on either.

A dry cell is a failure

  • Once dry, a cell stops conducting — so its neighbours dry too
  • MODFLOW-2005 cannot rewet a dry cell unless you enable the wetting capability, which is itself unstable
  • The failure propagates, and the budget goes with it

If you find dry cells, the honest reading is: the pumping is unphysical, the layer bottom is too shallow, you needed more layers, or you should be using MODFLOW-NWT, which handles dewatering properly.

“Report the heads with the dry cells masked out” is not on that list.
