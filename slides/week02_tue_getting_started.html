Three ways to run Python

1. The interpreter (REPL)

Type a line, get an answer, line is gone.

$ python
>>> 2 + 2
4
>>> exit()

Good for: “what does this function return again?”

Bad for: anything you want to keep.

2. A script

A plain text file, run start to finish.

$ python analyze_wells.py

Good for: work that is finished, repeated, or automated. Pipelines.

Bad for: exploring, when you want to see each step.

We come back to scripts in Week 15, once you have something worth automating.

3. A notebook

Cells you run in any order, output kept inline next to the code.

Good for: exploration, teaching, showing your reasoning.

Bad for: anything that must run the same way twice — unless you are careful.

This course lives in notebooks for Weeks 2–14, then deliberately moves out of them in Week 15. Both halves matter.

The notebook mental model

A notebook has two separate things:

The document

The cells you see, top to bottom. Just a file.

The kernel

A Python process holding every variable you’ve defined. Invisible.

The document has an order. The kernel has a history. These are not the same, and confusing them will cost you an afternoon at some point this semester.

The trap

# cell 1
depth = 50
# cell 2
depth = depth * 2
# cell 3
print(depth)

Run 1 → 2 → 3, you get 100. Run 1 → 2 → 2 → 3, you get 200. The notebook looks identical either way.

The fix: Restart Kernel and Run All Cells before you submit anything. If it doesn’t survive that, it isn’t finished.

Your turn: an aquifer volume

A confined aquifer is 4200 m long, 1800 m wide, and 25 m thick, with a porosity of 0.28. Fill in the blank to compute the volume of water it holds, in m³.

Hint

The bulk volume is length × width × thickness. Porosity is the fraction of that bulk volume which is void space.

Solution

volume_of_water = length * width * thickness * porosity

That’s 52,920,000 m³ — about 43,000 acre-feet. Units are your problem, not Python’s; it will happily multiply nonsense together.

Variables are names, not boxes

head_upstream = 412.5
head_downstream = 408.2

A name on the left, an expression on the right. The = is assignment, not equality.

Rules that will save you grief:

  • Names are case sensitive: Head and head are different
  • Use snake_case, not camelCase — that’s the Python convention
  • Never name something list, sum, type, or dict; you’ll break the builtin

Your turn: hydraulic gradient

Two wells are 850 m apart. Compute the hydraulic gradient \(i = \dfrac{\Delta h}{\Delta l}\) between them.

Hint

\(\Delta h\) is the head drop between the two wells. The variables head_upstream, head_downstream, and distance are already defined.

Solution

gradient = (head_upstream - head_downstream) / distance

0.00506 — dimensionless, and small, as gradients usually are.

Environments

The problem

Your code needs numpy. Which numpy?

  • Your laptop has one version
  • My laptop has another
  • The version that existed when a 2019 tutorial was written is a third
  • Half of “it works on my machine” is really “I have different packages”

An environment is a pinned set of packages that belongs to one project.

Our setup

We use GitHub Codespaces: a Linux machine in the browser, with the environment already built.

  • Open the course repo → Code → Codespaces → Create codespace
  • Wait ~2 minutes the first time
  • Python, Jupyter, and every package are already installed
  • The MODFLOW binaries are already downloaded

Nothing to install on your own machine. Nothing to break. If your codespace gets into a bad state, delete it and make a new one — that is the point.

These tools are different layers

Layer Its job in this course
Git Records the history of changes to files
GitHub Hosts the shared repository and coordinates copies
Codespaces Runs the remote Linux computer that holds the repo
VS Code Gives you the editor, terminal, and notebook interface
Jupyter kernel Runs Python and remembers the current variables

When something breaks, name the layer first. A Git sync problem, a Codespaces build problem, and a stopped Jupyter kernel need three different fixes.

Packages

import brings tools into reach

Python starts small on purpose. Even sqrt isn’t there until you ask.

import math gives you the module. math.sqrt reaches inside it. The math. prefix is not noise — it tells the reader where sqrt came from.

Three forms you’ll see

import numpy                    # numpy.mean(...)
import numpy as np              # np.mean(...)      ← use this
from numpy import mean          # mean(...)         ← avoid

The aliases are conventions, not rules — but they are universal conventions. np, pd, plt. Write them any other way and every example on the internet stops matching your code.

from x import * imports everything into your namespace and makes it impossible to tell where a name came from. Don’t.

Your turn: Darcy’s law

Darcy’s law for one-dimensional flow:

\[q = -K \frac{dh}{dl}\]

where \(q\) is specific discharge (m/d) and \(K\) is hydraulic conductivity (m/d).

Compute \(Q = qA\), the volumetric flow, through a 25 m × 1800 m cross-section with \(K = 12\) m/d and the gradient you found earlier.

Hint 1

q is \(K\) times the gradient. Ignore the minus sign — it only encodes that flow runs downhill, and we already know which way that is.

Hint 2

Once you have q, the volumetric flow is just q * area.

Solution

q = K * gradient
Q = q * area

About 0.0607 m/d and 2731.8 m³/d. Those f"{q:.4f}" bits are f-strings — Thursday’s session covers them.

Note the setup cell kept the gradient unrounded. Had we used 0.00506 we’d get 2732.4 — a small difference here, but rounding intermediates is how you end up off by a factor of two in a Week 12 water budget.
