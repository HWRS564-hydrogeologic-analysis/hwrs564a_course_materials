Today’s data is real: every USGS monitoring well in the Tucson basin.

Labels

The problem with position

data[3, 7]     # ...which well, and which measurement?

You wrote that line knowing what column 7 was. Three weeks later you don’t, and neither does anyone reading your code.

Worse: you insert a column at position 2, and every index after it is now silently wrong. Nothing errors. The numbers just change.

A DataFrame

wells.loc["320824110593001", "well_depth_ft"]

Same lookup, and it says what it means. If a column moves, this keeps working. If a column disappears, you get a KeyError — loudly, at the right place.

pandas is numpy with labels on it. Everything you learned last week still applies underneath.

The two objects

Series

One column. Values plus an index.

wells["well_depth_ft"]

DataFrame

A dictionary of Series that share an index.

wells[["site_no", "well_depth_ft"]]

One name in brackets gives a Series. A list of names gives a DataFrame. That is the whole rule, and it explains most of the double brackets you’ll see.

Reading data

read_csv, with one precaution

from pathlib import Path
import pandas as pd

ROOT = next(p for p in Path.cwd().parents if (p / "pyproject.toml").exists())
wells = pd.read_csv(ROOT / "data" / "tucson_basin_wells.csv",
                    dtype={"site_no": str})

dtype={"site_no": str} is not decoration. Site numbers are 15-digit identifiers; pandas would read them as integers, drop leading zeros, and break every join you make later — without a warning.

Walking up to find the repo root beats counting ../.., which works right up until you move the file.

Four things to check, every time

  1. df.dtypes — is anything a string that should be a number?
  2. df.isna().sum() — how much is missing, and where?
  3. df.describe() — do the numbers look physical?
  4. len(df) — did you get the number of rows you expected?

Thirty seconds. It catches the mistakes that otherwise survive all the way into a figure.

What that finds in the real thing

One well in five has no depth on file. In the full inventory it is 184 of 1,693 — and every filter you write on depth will silently drop them.

Selecting columns

Your turn: land surface in metres

Add a column land_surface_elev_m, then find the mean well depth in feet.

Hint

Assigning to a column name that doesn’t exist creates it. The arithmetic is elementwise, exactly like numpy.

Solution

wells["land_surface_elev_m"] = wells["land_surface_elev_ft"] * FEET_TO_M
mean_depth = wells["well_depth_ft"].mean()

350.8 ft. Note that .mean() skips missing values silently — with a None in the column you would get the mean of the three that remain, and no indication that you did.

.loc and .iloc

Labels vs. positions

.loc[]

By label — the index value and the column name.

wells.loc["320824110593001",
          "well_depth_ft"]

.iloc[]

By integer position, like numpy.

wells.iloc[3, 1]

They look interchangeable on a fresh DataFrame only because its index happens to be 0, 1, 2, .... Set a real index and they part company immediately.

The slice trap

.loc slices are inclusive of the endpoint. Every other slice in Python is half-open. This is genuinely inconsistent, it is not going to change, and it catches everyone exactly once.

Your turn: pull one well

Using .loc, get the depth and land surface elevation of well "C-22".

Hint

.loc takes rows first, then columns: .loc[row_label, column_labels]. You want both columns, so pass a list of the two names — or just the row label on its own.

Solution

one_well = wells.loc["C-22", ["well_depth_ft", "land_surface_elev_ft"]]

wells.loc["C-22"] alone works too and gives the whole row. Naming the columns explicitly is worth the extra characters when the table is wide — it documents what you actually needed.

Your turn: .loc or .iloc?

The index here is site numbers, not integers. Get the third row by position, and the well "C-22" by name.

Hint

“Third row” is a position. "C-22" is a label. One accessor each.

Solution

third_row = wells.iloc[2]
by_name = wells.loc["C-22"]

Both return 835.0 here — because C-22 is the third row. That coincidence is exactly why this distinction is easy to get away with being vague about, right up until the day you sort the table.

Wrap up

What you did today

  • A DataFrame is numpy with labels, and labels survive a column moving
  • One name gives a Series; a list of names gives a DataFrame
  • dtype={"site_no": str} for anything that is an identifier, not a number
  • .loc is labels, .iloc is positions, and .loc slices include the endpoint
