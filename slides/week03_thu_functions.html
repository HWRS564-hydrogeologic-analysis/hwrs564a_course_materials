Why bother

Code is a research artifact

Code is read far more often than it is written — usually by future you.

  • Names, spacing, and docstrings reduce the work of reconstructing intent
  • Common conventions let a reader focus on the science instead of your style
  • Reusable code can be checked, extended, and cited; opaque code cannot

You would not leave a field notebook with unlabeled units. Treat analysis code with the same care: it is part of the evidence behind the result.

The problem functions solve

q_well_a = 12.0 * (412.5 - 408.2) / 850
q_well_b = 12.0 * (409.1 - 404.8) / 620
q_well_c = 8.5 * (405.0 - 401.9) / 740

Three copies of one idea. Now the conductivity for well B turns out to be wrong, or you realise Darcy’s law needs a minus sign.

You have to find and fix every copy, and you will miss one. That is not a discipline problem — it is a structural one, and the structure is the fix.

The same thing, once

def specific_discharge(hydraulic_conductivity, head_drop, distance):
    """Darcy specific discharge q = K * dh/dl, in m/d."""
    return hydraulic_conductivity * head_drop / distance
q_a = specific_discharge(12.0, 412.5 - 408.2, 850)
q_b = specific_discharge(12.0, 409.1 - 404.8, 620)

One place to fix. One place to test. And the call site now says what it means instead of making the reader decode arithmetic.

Anatomy

def transmissivity(hydraulic_conductivity, thickness):
    """Transmissivity T = K * b, in m2/d.

    Parameters
    ----------
    hydraulic_conductivity : float
        K, in m/d.
    thickness : float
        Saturated thickness b, in m.
    """
    return hydraulic_conductivity * thickness
  1. Header names the function and its inputs
  2. Indented body is the work the function owns
  3. Docstring records meaning and units
  4. return hands the result back to the caller

The docstring is not optional politeness. It is where the units live, and units are what you will actually forget. help(transmissivity) prints it.

print is not return

A function with no return returns None. It looks like it worked, because you saw the number — and then None propagates three cells downstream and errors somewhere unrelated.

Arguments

Defaults make the common case short

Arguments with defaults come after those without. Passing them by name at the call site — porosity=0.28 — costs nothing and makes the line readable a year later.

Your turn: write one

Write hydraulic_gradient(head_upstream, head_downstream, distance) returning the dimensionless gradient.

Hint

One line. The head drop divided by the distance — and it has to be return, not print.

Solution

return (head_upstream - head_downstream) / distance

0.00506. Keep this one — you will call it again in Week 4 and again in Week 11 when you set up a MODFLOW boundary condition.

Refuse input that makes no sense

def safe_transmissivity(hydraulic_conductivity, thickness):
    if thickness < 0:
        raise ValueError(f"thickness must be positive, got {thickness}")
    return hydraulic_conductivity * thickness

A negative thickness is not a thin aquifer. It is a mistake somewhere upstream, and a function that quietly returns a negative transmissivity lets that mistake travel into a figure.

Fail loudly, near the mistake. A model that stops with a clear message costs you two minutes. One that returns a plausible wrong answer costs you a week.

The call raises, which is the point — a porosity of 1.4 would have given you a seepage velocity slower than the specific discharge, which is physically backwards and would have looked merely surprising rather than wrong.

Note <= 0 rather than < 0: a porosity of exactly zero divides by zero.

Comprehensions

A loop that builds a list, in one line

# the long way
depths_ft = []
for d in depths_m:
    depths_ft.append(d * 3.28084)

# the comprehension
depths_ft = [d * 3.28084 for d in depths_m]

Read it right-to-left: for each d in depths_m, give me d * 3.28084.

Filter by putting an if at the end:

deep = [d for d in depths_m if d > 40]

Your turn: names of the deep wells

Build a list of the IDs of wells deeper than 40 m — one comprehension, no loop.

Hint 1

zip(wells, depths) works inside a comprehension exactly as it does in a for loop.

Hint 2

The shape is [<what to keep> for w, d in zip(...) if <condition>]. You want to keep w but test d.

Solution

deep_wells = [w for w, d in zip(wells, depths) if d > 40]

['B-07', 'C-22', 'E-11'].

Use a comprehension when it fits on a line and reads like a sentence. When it needs two conditions and a nested loop, write the for loop — clever is not the goal.

Modules

Other people’s functions

The math. prefix is not noise — it tells the reader where sqrt came from. When you see sqrt(2) bare, you have to go hunting for which of five imports supplied it.

Your own functions are a module too

Put functions in wells.py, and from a notebook in the same folder:

import wells
wells.transmissivity(12.0, 25.0)

This is how a notebook stops being a wall of code: the reasoning stays in the notebook, the machinery moves to a .py file next to it.
